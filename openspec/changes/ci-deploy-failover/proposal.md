# CI-деплой с резервным SSH-сервером

## Почему

CI сейчас деплоит тестовый и production-инстанс только на основной VPS. Если
SSH-сессия или удалённый deploy зависает до общего таймаута job, workflow
завершается без попытки доставки на резервный сервер.

## Что меняется

- Сохранить `45.128.235.219` основным SSH-target по умолчанию.
- Добавить ограниченную по времени попытку деплоя на основной target и запуск
  на `litteraly@89.34.219.35` только при явном timeout этой попытки.
- Не скрывать обычные ошибки деплоя и failed health check повторным запуском на
  другом сервере.
- Добавить отдельный restricted-user deploy path для `/opt/meatproxy-prod` и
  `/opt/meatproxy-test`, используя системный Bun и sudo только для restart
  заранее установленных units.
- Описать обязательную подготовку пассивного сервера и ограничения Telegram
  long polling.

## Не входит

- Изменение DNS, Cloudflare Load Balancer или Cloudflare Tunnel.
- Автоматическое переключение активного Telegram-инстанса между VPS.
- Копирование production `.env`, SQLite или аудиокэша.
