# Design: grant-generation-credits-to-all

## Решение

Добавить в `users-store` функцию массового начисления, которая в одной SQLite
транзакции выполняет `UPDATE users SET credits = credits + 10` и создаёт строки
`grant_history` через `INSERT ... SELECT`. Возвращаемое число изменённых строк
используется как количество получателей.

API добавит `POST /api/admin/users/grant-credits-all`. Роут не принимает сумму:
операция намеренно фиксирована на 10 кредитов, чтобы кнопка не стала случайным
инструментом выдачи произвольного баланса. Аутентификация и роль проверяются
существующим `requireAdmin`; идентификатор администратора записывается в
`granted_by`.

Mini App разместит операцию в панели «Пользователи и выдачи». Перед запросом
показывается подтверждение с числом пользователей из загруженного списка.
После успеха список обновляется, а выбранный пользователь получает новый баланс
и свежую запись в истории.

## Совместимость и риски

- Схема БД не меняется: используется существующая таблица `grant_history`.
- Зарегистрированные пользователи — строки `users`; записи allowlist, которые
  ещё не обращались к приложению/боту, не считаются пользователями и не получают
  кредит до первого создания строки `users`.
- Транзакция не оставит частично начисленный массовый грант при ошибке записи
  истории.
- Повторное подтверждение является новой намеренной выдачей и снова добавит 10;
  UI подтверждает каждую операцию.
