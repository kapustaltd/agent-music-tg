# Design: fast-playlist-brand-refresh

## Решения

1. Служебная подпись удаляется условным рендерингом в `PromptScreen`: для AI
   остаётся основной заголовок, режим поиска сохраняет собственную подпись.
2. Логотип реализуется как inline SVG-компонент с концентрическими рядами
   точек разной прозрачности и размера. Это сохраняет резкость на Retina,
   не добавляет сетевой запрос и позволяет использовать знак в шапке и
   favicon.
3. Инициализация Mini App оставляет обычный `expand()` под заголовком Telegram,
   но не вызывает `requestFullscreen()`: полноэкранный режим не должен
   включаться без явного действия пользователя.
4. `DEFAULT_MAX_ITERATIONS` уменьшается с 12 до 4. Типичный путь остаётся
   двухходовым (`searchTracks` → `finalize_playlist`), а четвёртая итерация
   оставляет запас для повторного поиска или ответа без tool call. На
   предпоследней итерации существующее принуждение к финализации гарантирует,
   что агент не продолжает исследование до старого лимита.
5. Музыкальные запросы не переводятся на последовательные вызовы: текущие
   `SEARCH_CONCURRENCY` и `FINALIZE_CONCURRENCY`, общий cache и prewarm
   backend-ов уже уменьшают сетевую часть критического пути.
6. CheapVibeCode получает явные env-дефолты `deepseek-v4-flash` и
   `https://ru.cheapvibecode.ru/v1`. Старый сохранённый override основного
   домена нормализуется в провайдере, поэтому ручная правка БД не нужна.
7. HTTP-запрос к OpenAI-compatible провайдеру получает настраиваемый timeout,
   а общий агентский вызов ограничен 45 секундами. Fallback провайдера
   используется только для сетевых и 5xx ошибок, но не для 4xx-конфигурации.

## Совместимость

- SVG не требует новых пакетов и поддерживает обе темы через `currentColor`.
- Существующие незакоммиченные изменения пользователя в Mini App не
  перезаписываются.
- При превышении нового лимита сохраняется существующая ошибка/запасная
  финализация, а не создаётся пустой плейлист.
