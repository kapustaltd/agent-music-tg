# Design: обновление подбора и магазина

## Контекст

В проекте уже есть визуальная система Mini App и общий `Segmented` с
двигающимся индикатором, roving tabindex и поддержкой клавиш-стрелок. Профиль
использует этот компонент для «Источник треков». Платежи Stars и Platega уже
поддерживаются сервером и клиентским `BuyScreen`; задача меняет представление,
а не контракт оплаты.

## Решения

### D1. Один источник правды для переключателей

`PromptScreen` использует `Segmented` с `role="radiogroup"`, заполнением по
ширине и подписями «Подобрать» и «Поиск». Иконки не добавляются: сам контроль
должен выглядеть так же, как выбор источника треков, а смысл уже передан
текстом.

### D2. Поле запроса — главный объект на телефоне

На ширине до 839px карточка создания выходит за внутренний 14px gutter до
границ viewport, а `.prompt-pill` получает ширину viewport и нулевой внешний
радиус. Переключатель, подсказки и результаты сохраняют внутренние отступы.
На desktop layout не меняется.

### D3. Магазин строится вокруг срока

Mini App показывает только подписочные офферы с `grantAmount` 30, 90 или 180.
Сроки сортируются как 1 → 3 → 6 месяцев. Каждая кнопка плана показывает срок,
количество дней и доступные цены; выбор плана не создаёт счёт.

### D4. Оплата — отдельный последовательный шаг

После выбора плана показывается общий `Segmented` для доступных методов:
Platega/СБП и Telegram Stars. Единственная CTA создаёт счёт после явного
нажатия. Stars открывается через текущий Telegram invoice flow, Platega — через
текущий popup и polling. Если у оффера один метод, переключатель заменяется
нейтральной подписью.

### D5. Статус и история остаются плоским контентом

Текущий срок подписки показывается рядом с заголовком без вложенной декоративной
карточки. История оплат остаётся списком. Ошибка, success, loading и trial
сохраняются как отдельные состояния существующих компонентов.

## Риски и меры

- Если в базе пока нет офферов на один из трёх сроков, он не выдумывается и не
  появляется с пустой ценой; витрина показывает только реально доступные планы.
- Цена одного метода может отсутствовать — `Segmented` получает только
  доступные методы, поэтому CTA не открывает заведомо нерабочий поток.
- Full-bleed поле не должно вызвать горизонтальный scroll: ширина и margin
  рассчитываются относительно viewport, а общий shell сохраняет `overflow-x:
  clip`.

## Проверка

1. `bun run typecheck`.
2. `bun run build:miniapp`.
3. `bun test` для регрессий платежных потоков и общего API-контракта.
4. Ручной просмотр prompt и shop в dark/light на ширинах 320px и 390px;
   проверить переключение режима, выбор плана, Stars, Platega, loading/error и
   отсутствие горизонтального overflow.
