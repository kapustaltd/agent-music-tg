# improve-generation-loading-ui — Design

## Current problems

`GenerationStatus` рендерит фазу и счётчик в одну строку, добавляет многоточие независимо от смысла текста и использует `TrackRow` внутри `prompt-card`. Финальный CSS возвращает этому состоянию нижнюю границу статуса и границы строк. Одновременно `PromptScreen` показывает запрос с нижней границей, поэтому loading-экран получает несколько параллельных линий и слабый вертикальный ритм.

## Decisions

### D1. Статус в два уровня

`title` берётся из последней безопасной фазы SSE (`Ищу подходящие треки`, `Сверяю исполнителей`, `Собираю плейлист` и т. п.). `detail` показывает `foundLabel()` или `Подбор начался`. Это позволяет быстро считать состояние сканированием и не смешивает действие агента с результатом поиска.

### D2. Треки остаются контентом, не карточками

Превью использует текущий `TrackRow`, чтобы не менять проигрывание и доступность. Стили генерации убирают `border`, `border-bottom`, inset-shadow и фон по умолчанию. Между строками используется только небольшой вертикальный gap; фон разрешён лишь как hover/pressed feedback.

### D3. Контекст запроса без полосы

Во время `prompt-card--busy` запрос остаётся доступным и редактируемым, но его нижняя граница и лишний отступ удаляются. В обычном состоянии существующая структура не меняется.

### D4. Loading без декоративной шкалы

Индикатор активности остаётся маленьким `CircleNotch`, потому что генерация действительно идёт. Отдельные progress bars, shimmer, repeating gradients, blinking cursor и пульсирующие точки для этой задачи не добавляются: протокол не передаёт достоверный процент, а полоска будет создавать ложную точность.

### D5. Адаптивность и motion

Статус переносится на узких экранах, счётчик не обрезается, превью сохраняет touch target строки. При `prefers-reduced-motion: reduce` вращение отключается существующим общим правилом `.spin`; layout и статические подсказки остаются доступными.
