# Чек-лист ревью

Применять только пункты, относящиеся к diff. Для пропущенной обязательной проверки
указать причину и оставить её открытой. Не выставлять выдуманный «балл качества».

## Общие проверки

- Изменение соответствует запросу и критериям; нет случайных рефакторингов.
- Есть воспроизводимое доказательство исправления, если менялась логика.
- API и сохранённые данные совместимы; пользовательские тексты на русском.
- Ошибки обработаны, ресурсы освобождаются, повторные операции ограничены.
- Документация описывает действительное поведение; проверки относятся к текущему diff.

## Backend: server

- Allowlist и admin-права проверяются сервером, а не только интерфейсом.
- Платежи идемпотентны; валюта и minor units не теряются; повторный callback безопасен.
- Миграции сохраняют существующие данные; старые provider/backend имеют явный fallback.
- Сетевые запросы и фоновые задачи имеют timeout; retry ограничен и не дублирует списание.
- Аудио не оставляет временные файлы и зависшие блокировки; конкурентность ограничена.
- SSE корректно завершает успех и ошибку; отключение клиента не создаёт утечек.
- Тесты используют моки и временные/ in-memory БД, не реальные сообщения и оплаты.
- Секреты и персональные идентификаторы не попадают в ошибки клиенту и диагностику.

## Frontend: miniapp и dashboard

- Проверены затронутые состояния loading/empty/error/success и недоступные действия.
- Hooks и обработчики очищают подписки, таймеры и запросы; устаревший ответ не затирает новый.
- Telegram WebView, safe-area, клавиатура и узкий экран учтены для Mini App.
- Элементы доступны с клавиатуры, имеют понятные подписи; reduced motion учитывается.
- Стили следуют DESIGN.md; новая правка не добавляет очередной слой конфликтующих overrides.
- Проверены API/SSE-контракты, состояние плеера и обратная совместимость там, где они затронуты.
- Визуальные изменения проверены в браузере; факт сборки не выдаётся за визуальное ревью.

## CI и инструкции агентам

- Локальные команды и workflow согласованы; обязательные ошибки не скрыты.
- Проверенный SHA не заменяется движущейся веткой в следующих этапах.
- Production остаётся ручным этапом; агент не запускает deploy-скрипты.
- Инструкции не требуют несуществующих команд, навыков или необязательных подтверждений.
- Ссылки, команды и шаблоны доступны из чистого checkout, без личной конфигурации автора.
