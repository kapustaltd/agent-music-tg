# Аудит легаси и проверок — 2026-09-22

Аудит исходников и локальный прогон проверок; нагрузочные измерения и проверка
production не проводились. Большой файл сам по себе не доказывает проблему
производительности. Ниже разделены подтверждённые пробелы и следующий объём работ.

## Исправлено в этой итерации

- Единая команда `bun run check`: типы сервера, все тесты, сборки Mini App и dashboard
  с их проверкой типов. Раньше dashboard отсутствовал в CI.
- `bun run test` изолирует каждый тестовый файл. Раньше CI отдельно запускал только
  `run-generation.test.ts`, хотя глобальные моки есть также в API и bot-тестах.
- Проверенные frontend-бандлы сохраняются как артефакты на 7 дней. Имена содержат SHA.
- Deploy jobs используют SHA из verify: перемещение ветки между этапами больше
  не меняет выбранные исходники.
- Production запускается только вручную с `deploy_production`, как описано в README.
  Раньше условие workflow также разрешало production после обычного push.
- Все jobs ограничены 20 минутами. Новые зависимости не добавлялись.

Из `ai-slop-detector` перенесён подход «единая проверка → сборки → артефакты →
зависимые deploy jobs», адаптированный к Bun и двум frontend-приложениям.
Артефакты пока служат для проверки результата: существующие deploy-скрипты всё ещё
пересобирают frontend. Это ещё не модель «собрать один раз и продвигать тот же архив».

## Что не удалять как «легаси»

Миграции в `server/migrations.ts`, чтение старых invoices/generations и атрибуция
`unknown / legacy` обеспечивают совместимость существующих данных. Их удаление
требует отдельного плана миграции и не является косметическим рефакторингом.
Обновления major-версий React/Vite и смена package manager в эту итерацию не входят.
